# W8 任务工作台聚合接口实现记录

## 1. 目标

为对话式运营工作台提供单任务聚合查询接口。前端进入任务页面时，不再依次请求任务、
数据快照、风险分、证据、确认记录、报告版本和执行步骤，也不需要自行推导当前应显示的
操作按钮。

## 2. 接口

```http
GET /api/tasks/{taskId}/workspace
```

任务不存在时返回 `TASK_NOT_FOUND`。

## 3. 返回内容

聚合响应包含：

- `task`：任务状态、当前步骤和失败信息；
- `data_snapshot`：最新企业事实、工商变化、结构化风险事件和数据源状态；
- `risk_score`：最新原始分、人工分、风险等级和规则命中；
- `evidence_progress`：证据总数、确认数、驳回数、未处理数、正文成功/失败数和风险类型分布；
- `latest_confirmation`：最近一次运营确认；
- `confirmation_state`：确认状态；
- `confirmation_ready`：当前输入是否具备确认条件；
- `report_generation_ready`：是否可立即生成或重试报告；
- `readiness_blockers`：阻止确认或生成报告的原因；
- `next_action`：建议前端突出显示的下一步操作；
- `reports`：任务全部报告版本；
- `steps`：任务执行步骤和重试记录。

任务尚未形成数据快照、评分或确认记录时，对应对象不返回，其他进度字段仍正常返回。

## 4. 确认状态

| 状态 | 含义 |
|---|---|
| `NOT_READY` | 缺少企业数据快照、评分，或评分不属于最新数据快照 |
| `PENDING` | 输入完整但尚未进行运营确认 |
| `VALID` | 最新确认与当前数据、评分、人工调整和证据状态一致 |
| `STALE` | 确认后输入发生变化，需要重新确认 |

## 5. 阻塞原因

| 阻塞码 | 含义 |
|---|---|
| `DATA_SNAPSHOT_MISSING` | 尚未形成企业数据快照 |
| `RISK_SCORE_MISSING` | 尚未计算风险分 |
| `RISK_SCORE_NOT_FROM_LATEST_DATA` | 最新评分不属于最新数据快照 |
| `UNVERIFIED_EVIDENCE` | 仍有公开证据未确认或驳回 |

## 6. 下一步动作

`next_action` 是服务端根据任务状态和数据完整性计算的 UI 建议，不会自动执行写操作。

| 动作 | 前端建议 |
|---|---|
| `EXECUTE_TASK` | 显示“继续执行” |
| `CONFIRM_SUBJECT` | 显示企业主体候选确认 |
| `REVIEW_EVIDENCE` | 打开待处理舆情证据 |
| `CALCULATE_RISK` | 显示“计算风险分” |
| `CONFIRM_REVIEW` | 显示运营确认卡片 |
| `GENERATE_REPORT` | 显示“生成报告” |
| `RETRY_TASK` | 显示失败步骤重试 |
| `RETRY_REPORT` | 显示报告生成重试 |
| `WAIT` | 显示处理中状态 |
| `DOWNLOAD_REPORT` | 显示报告版本与下载入口 |
| `NONE` | 不提供主操作 |

## 7. 前端使用建议

工作台首屏只请求 `/workspace`：

1. 使用 `task` 和 `next_action` 渲染顶部状态及主按钮；
2. 使用 `data_snapshot.company_facts` 渲染企业概览；
3. 使用 `risk_score` 渲染原始分、人工分和等级；
4. 使用 `evidence_progress` 渲染证据处理进度；
5. 使用 `confirmation_state` 判断确认卡片是否显示“有效”“待确认”或“已失效”；
6. 使用 `reports` 渲染历史报告版本。

证据正文、完整检索结果等大数据仍通过原明细接口按需加载，避免首屏响应无限膨胀。

## 8. 验证覆盖

自动化测试覆盖：

- 新建任务：缺少快照和评分，建议继续执行；
- 未知任务：返回 `TASK_NOT_FOUND`；
- 证据未处理：显示 `UNVERIFIED_EVIDENCE` 和 `REVIEW_EVIDENCE`；
- 有效确认：允许生成报告；
- 人工改分后：确认变为 `STALE`，建议重新确认；
- 重新确认并生成报告：完成态建议下载报告；
- OpenAPI 包含聚合接口和返回模型。
