# W4 旧报告与 DOCX 纵向链路实现记录

## 1. 结论

W4 已完成“旧报告读取—内容解析—输入冻结—新版 DOCX 生成—版本留痕—差异查询—文件下载”的纵向链路。实现继续遵守 V1 范围：只服务单企业旧风险报告更新，不在本阶段引入多 Agent 编排、审核流、PDF 产品输出或在线 ES。

## 2. 端到端流程

```text
任务已完成主体识别与结构化数据冻结
    ↓
取得最新 DataSnapshot
    ↓
取得最新 RiskScoreSnapshot
    ↓
按 previous_report_file_id 读取旧 DOCX
    ↓
解析旧报告的公司、日期、评分、结论和可复用章节
    ↓
计算本次输入哈希与报告差异
    ↓
命中相同输入哈希 → 复用已有 GENERATED 版本
未命中 → 创建 GENERATING 版本并渲染
    ↓
原子写入本地报告存储，记录内容 SHA-256、文件大小和版本
    ↓
通过 API 查询版本、差异或下载 DOCX
```

## 3. 模块职责

| 模块 | W4 职责 |
|---|---|
| `atlas-domain` | `PreviousReport`、`ReportDiff`、`ReportVersion`、`ReportStatus` 等稳定领域模型 |
| `atlas-application` | 报告生成用例、幂等判断、版本编排、差异计算、端口定义 |
| `atlas-adapter-docx` | OOXML 旧报告解析、正式模板受控渲染、本地旧报告来源 |
| `atlas-adapter-storage` | 报告版本 JDBC Repository、本地生成文件存储、Flyway V4 |
| `atlas-api` | 生成、列表、差异、下载接口和报告错误语义 |
| `atlas-bootstrap` | 模板、旧报告根目录、文件存储根目录的装配与配置 |

## 4. 版本与幂等契约

- 输入哈希覆盖任务、数据快照、评分快照、旧报告内容和模板版本；
- 同一任务命中相同输入哈希且状态为 `GENERATED` 时返回已有报告；
- 任一有效输入发生变化时创建新的递增版本；
- 已生成版本不覆盖，状态可扩展为 `SUPERSEDED`；
- 数据库存储 `input_hash`、`content_hash`、`data_snapshot_id`、`score_snapshot_id`、解析结果、差异、失败原因和操作人；
- 下载只允许 `GENERATED` 状态，并在响应头返回内容 SHA-256。

## 5. 数据刷新边界

W4 只用已经冻结且可追溯的结构化数据刷新企业基本信息、工商变更、结构化风险和评分。公开舆情、失联、欠薪、闭店等不能仅凭原始搜索文本自动确认；在 W5 搜索、证据核验和模型研判接入前，这些章节保留旧报告内容或显示当前无已确认新增事件。

这是刻意设置的证据门禁，不是生成能力缺失：未经核验的外部文本不得直接改变评分或风险事实。

## 6. 失败语义

- 旧报告不存在、不是有效 DOCX、模板不受支持或关键解析结果不足：请求失败并记录验证错误；
- 缺少企业快照或评分快照：停止生成；
- 渲染或存储失败：报告版本记为 `FAILED`，保存安全化失败原因；
- 查询不属于当前任务的 `reportId`：按不存在处理，避免跨任务泄露；
- 失败不会覆盖此前成功版本。

## 7. 测试与验收

- 旧报告解析测试覆盖公司名称、报告日期、评分、风险等级和受控章节；
- 模板渲染测试覆盖字段替换、行业 JSON 可读化、空数组清理和空工商变更占位；
- 应用测试覆盖生成幂等、版本递增、差异、失败和下载；
- API 集成测试覆盖四个报告接口；
- 北京简熹和食品有限公司真实样本用于端到端回归；
- 最终 DOCX 需经过包结构校验、文本检查、Word 导出 PDF 和逐页视觉复核。

## 8. W5 入口条件

W5 在 W4 的报告版本和证据门禁上增量建设，至少包括：多搜索源 Provider、搜索请求与结果留痕、证据去重、可信度和时效判断、人工确认事件、模型研判结果结构化，以及由确认事件触发重新评分和新报告版本。
