# Atlas 备份恢复演练记录

## 1. 结论

2026-08-18 在 `10.210.0.62` 完成 Atlas V1 首次隔离备份恢复演练，结果为 `PASS`。
演练覆盖 PostgreSQL、正式报告文件卷、历史任务兼容文件卷、`.env`、Compose 定义、部署文件
和默认 DOCX 模板。恢复使用独立临时数据库和 `/tmp` 临时目录，没有覆盖生产数据库、ES 或
现有报告文件。

## 2. 备份产物

- 备份目录：`/opt/atlas-backups/20260818T093605Z`
- 总大小：约 5.2 MB
- PostgreSQL 自定义格式备份：约 781 KB
- 正式报告文件卷：31 个文件，压缩后约 1.9 MB
- 历史任务兼容文件卷：23 个文件，压缩后约 2.5 MB
- 配置、部署文件和默认模板：约 69 KB
- 所有文件权限为 `600`，所有者为 `root`
- `SHA256SUMS` 覆盖数据库、行数基线、两个文件卷、文件内容清单和配置归档

备份中的 `.env` 含运行凭据，当前通过宿主机目录和 `600` 权限限制访问，但尚未做独立加密。
正式生产备份还应配置加密密钥、异机副本、保留周期和定期自动执行。

## 3. 恢复验证

演练编号：`20260818T093629Z`。

1. 所有备份包的 SHA-256 校验均为 `OK`。
2. PostgreSQL 恢复到临时数据库 `atlas_restore_drill_20260818093629`。
3. Flyway 版本及任务、快照、证据、评分、研判版本、报告、会话和任务事件等关键表行数与
   备份基线完全一致。
4. 正式报告文件恢复到临时目录，31 个文件逐文件 SHA-256 完全一致。
5. 历史任务兼容文件恢复到临时目录，23 个文件逐文件 SHA-256 完全一致。
6. 配置归档成功解压，`.env`、`compose.yaml`、`deploy/` 和 `data/templates/` 均存在且非空。
7. 演练结束后临时数据库和临时目录自动删除；只剩 `postgres`、`atlas`、`template1` 和
   `template0` 四个正常数据库。
8. 演练后 Atlas 后端健康状态为 `UP`。

服务器备份目录中的 `restore-drill-result.txt` 保存了机器可读结果。

## 4. 可复用命令

从 `/opt/atlas-agent` 执行：

```bash
scripts/backup-docker.sh /opt/atlas-backups
scripts/restore-drill-docker.sh /opt/atlas-backups/<备份批次>
```

恢复脚本只允许恢复到自己创建的临时数据库和 `/tmp/atlas-restore-drill-*` 目录，并在退出时
清理，不提供覆盖生产库的快捷路径。

## 5. 本轮边界

本轮已经证明业务数据库、报告文件和服务器运行配置能够从备份中完整恢复。以下事项不在本轮
范围内，仍应在正式生产准备阶段单独完成：

- ES 源数据的快照与恢复；当前 ES 属于百企业验证数据，企业源数据备份策略需随生产 ES 确定；
- 备份加密、异机/对象存储副本、自动调度、监控告警和保留策略；
- 整机故障后从空服务器重建；
- 应用镜像回滚及数据库向前迁移兼容演练。
