# 搜索准入、对话归档、报告差异与待处理布局优化记录

日期：2026-08-18

## 本轮目标

- 减少 Tavily 返回的百科、企业档案和普通词条进入风险证据池；
- 支持移除无用对话，同时保留任务、报告和审计记录；
- 明确同一企业多次排查不会自动合并；
- 将“查看差异”从原始接口升级为运营人员可读的版本比较页；
- 调整待处理页左右宽度并去除详情区嵌套滚动。

## 实现结果

1. 搜索继续采用“Atlas 编排 + Tavily 检索”的组合。Atlas 在 Tavily 结果进入主体匹配前增加风险准入：百科、工商档案、企业简介等背景页面在没有明确风险事实时直接过滤；页面若同时包含失联、欠薪、闭店、处罚、执行、破产、投诉等明确风险词，仍可保留。默认仍为三组查询，避免未经业务确认就把调用次数和费用扩大一倍。六组精细查询仅登记为未来连接器草稿模板，未发布到当前运行版本。
2. 对话新增软归档接口和删除入口。删除只让对话退出当前操作人的最近列表，不删除关联任务、报告、证据决定或审计记录。数据库迁移为 V21。
3. 同一企业的历史对话显示“同企业 N 次”。新建同企业排查时，系统提示选择打开既有对话或创建一次独立排查；不同日期、不同证据批次和不同报告版本不自动合并。
4. 报告库的“查看差异”进入独立页面，比较相邻版本的报告版本、日期、原始分、人工分、风险事项数量和模板版本。首版报告明确提示没有上一版本；正文逐段红线比较仍未纳入本版。
5. 待处理页在宽屏采用约 4:6 的列表/详情比例，详情区取消独立滚动条，统一随页面滚动；1260px 以下自动切换单列。

## 验证

- 后端新增归档、搜索过滤和报告差异测试；相关回归 6 项通过。
- 前端 ESLint、生产构建和 20 项页面契约测试通过。
- 已部署到 `10.210.0.62`；数据库最新迁移为 `21 | archive agent conversations | true`。
- Chrome 实测 `/pending`、工作台和 `/reports/diff`：布局、角色区分、归档入口、同企业次数及版本比较均正确，差异页首次加载的 React 文本不一致问题已修复，最终页面错误为 0。
- 上线后实际点击归档暴露 CORS 仅允许 `GET/POST`、浏览器 `DELETE` 预检被拦截的问题；已将业务 API 允许方法补齐为 `GET,POST,DELETE,OPTIONS`，增加预检集成测试并重新部署。线上预检响应现明确返回 `Access-Control-Allow-Methods: GET,POST,DELETE,OPTIONS`。

## 保留边界

- 本轮不覆盖历史人工确认或排除结果，避免改变已经生成的报告与审计结论。
- 是否对历史证据另起批次重新评估，需要业务确认。
- 是否把当前三组 Tavily 查询扩为六组，需要在质量抽样与调用成本之间另行确认。
