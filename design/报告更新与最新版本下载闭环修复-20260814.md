# 报告更新与最新版本下载闭环修复

日期：2026-08-14  
验证任务：`AT-20260813-1C30162C`  
部署环境：`10.210.0.62`

## 问题

运营人员在已有对话输入“更新报告”后，Agent 只返回任务已完成并建议下载；下载得到的仍可能是
旧版本。问题并非报告生成器未升级，而是指令执行和下载解析之间存在断点：

1. 带任务上下文的“更新报告”被确定性解析为状态查询，没有调用报告生成服务。
2. 历史消息的下载动作保存了当时的具体 `report_id`，后续新版本生成后旧按钮不会更新。
3. 任务工作台对后端已按版本倒序返回的报告列表再次反转，可能选中最早版本。

## 修复

- 已完成任务收到“更新报告、刷新报告、重新生成报告、生成最新报告”时，调用当前报告生成链路。
- 报告输入哈希未变化时返回已有最新版本；模板、渲染器、快照、评分、证据或确认发生变化时生成
  新版本。
- 已完成任务重新生成失败时保留原任务 `COMPLETED` 和原可下载版本，不把既有成果改成失败。
- 新增最新版本下载接口：`GET /api/tasks/{taskId}/reports/latest/download`。
- Agent 新消息和前端历史消息均使用任务 ID 动态下载最新版本，不再依赖消息中固化的报告 ID。
- 任务工作台直接从倒序列表选择首个 `GENERATED` 报告。
