# W26 黄金样本验收基础设施实现记录

## 当前结论

W26 的技术基础设施已完成，正式业务盲测尚未完成。当前工作区只有 1 份正式报告模板，没有 20～50 组历史旧报告与人工终稿，因此不能用合成样本宣布生产验收通过。

## 已实现

- 新增独立“验收评估”平台入口；
- 新增 `atlas-acceptance.v1` 业务黄金样本清单与 JSON Schema；
- 每个样本记录企业全称、信用代码、简称/品牌身份词；
- 每个样本引用旧报告、人工终稿、企业 JSON 和人工决策；
- 记录原始分、人工分、风险等级和逐条舆情标签；
- 舆情标签包含风险类型、来源链接、命中的身份词、主体归属、是否进入报告和是否重大风险；
- 重大风险必须主体匹配、进入报告且具有来源链接，否则拒绝导入；
- 少于 20 份、存在未业务确认样本或真实资料文件未验证时，样本集只能处于 `DRAFT`；
- 服务端逐份验证四类资料路径没有越界、文件存在、大小受控、JSON 可解析、DOCX 具有 ZIP 签名；
- 正式盲测逐份记录主体正确性、重大风险证据覆盖、评分解释、DOCX 核心字段、Critical/High 缺陷和人工分钟数；
- 所有通过项默认不勾选，必须由运营人员逐项确认；
- 每轮验收形成不可覆盖的独立记录并进入统一审计；
- Docker 中真实黄金样本资料使用现有持久化文件卷 `/data/files/golden`。

## 正式门禁

一轮结果只有同时满足以下条件才为 `PASSED`：

1. 样本数为 20～50 份；
2. 所有样本均由业务确认；
3. 所有旧报告、人工终稿、企业 JSON 和人工决策文件均通过服务端验证；
4. 严重主体错配为 0；
5. 所有重大风险均有可访问证据；
6. 所有样本评分差异可解释；
7. 所有 DOCX 核心字段通过；
8. Critical 与 High 缺陷均为 0。

## 当前所需真实资料

最少提供 20 组“历史旧报告 DOCX + 人工修改终稿 DOCX”。若文件名或子目录能清楚对应同一企业，后续可由开发侧从已有 `company_data` 抽取企业 JSON，并根据两份报告差异生成待确认的人工决策清单，减少运营整理工作。评分预期、证据归属和是否业务确认仍必须由实际运营人员确认。
