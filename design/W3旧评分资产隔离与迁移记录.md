# W3 旧评分资产隔离与迁移记录

## 1. 结论

旧代码不能作为一个在线服务直接包装。`CompanyStandardService.updateRiskInfo` 是批处理编排入口，`RiskScoreService` 同时承担数据读取、规则计算、地区特例、人工干预保护和 ES 写入。W3 已建立无外部副作用的 `RiskScoreEngine`，先安全保留物化旧分，再逐条迁移纯规则。

## 2. 代码边界

| 旧资产 | 实际职责 | W3 处理 |
|---|---|---|
| `RiskEnum` | 39 个风险标签、旧标签号和旧 ES 索引名 | 迁移为 `RiskType`；保留旧标签号/索引仅用于追溯，新增 `STORE_CLOSURE` |
| `updateRiskInfo` | 随机等待、读取企业、更新标签、动态预警、评分、保存 | 不迁移；拆成工作流、Provider、评分引擎和 Repository |
| `updateRiskLabel` | 读取风险 Map、地区地址、黑名单、关联风险并写标签 | 归入未来快照构建/发现核验，不进入评分引擎 |
| `setRiskLabel*` | 风险标签优先级评分，同时查询投诉服务并包含地区特例 | 纯规则待黄金样本回归后逐条迁移 |
| `scoreForPart1Base` | 基于舆情、投诉、文书、经营异常等计数加权 | 可纯化；待 W5 证据字段稳定后迁移 |
| `scoreForPart4` | 注册资本、成立年限等倍率 | 可纯化；旧代码使用系统当前时间，迁移时必须改用请求中的 `calculated_at` |
| `scoreForThisCompanyNew` | 聚合标签、行业、关联企业、基础分和倍率 | 可纯化；必须先把所有读取结果转换成标准输入 |
| `saveStatusAndScore` / `saveHisScore` | 人工干预保护、更新当前 ES、写历史 ES | 禁止进入引擎；改由 PostgreSQL Repository 和 `operator_decision` 完成 |

## 3. 当前可执行契约

```text
旧分基线 = snapshot.company_facts.additional_fields[risk_score | riskScore]
规则计算分 = LegacyRiskScoreAdapter(旧分基线)
事件最低分 = max(失联 6, 欠薪 6, 门店关闭 8)
原始分 = clamp(max(规则计算分, 事件最低分), 0, 10)
人工分 = 原始分（默认）
```

旧分、规则分、事件最低分、原始分、人工分、命中规则、规则版本、引擎版本和输入哈希分别保存。人工调整只更新 `manual_score`，并向 `operator_decision` 追加一条不可丢失的操作记录。

## 4. 已关闭风险

- 评分引擎不依赖 Spring、ES、数据库、缓存、队列或通知；
- 同一输入采用稳定哈希，持久层按任务和输入哈希幂等；
- 只有显式确认事件触发最低分，原始离线标签和未来搜索文本不能直接触发；
- 多个最低分规则取最大值，不相加；
- 人工分低于事件最低分允许保存，但返回 `floor_override_warning=true`；
- `OTHER` 改分原因必须至少 10 个字符；
- 风险等级直接使用原始精度判断，不先四舍五入。

## 5. 后续迁移门禁

旧规则细粒度迁移前仍需 20～50 份未被人工改分污染的黄金样本。每条规则迁移必须同时比较输入字段、规则命中、聚合中间值和最终分，不得只比较最终分。新规则通过回归后升级 `rule_version`，历史评分快照不重算、不覆盖。
