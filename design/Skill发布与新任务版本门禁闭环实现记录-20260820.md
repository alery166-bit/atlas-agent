# Skill 发布与新任务版本门禁闭环实现记录

日期：2026-08-20  
环境：`10.210.0.62` Docker DEV

## 1. 问题与结论

线上五个内置 Skill 自 2026-08-05 登记后一直只有 V1 草稿，没有 DEV 生效绑定；后台为了兼容
早期任务，在任务快照没有 Skill 时仍默认执行内置代码，造成页面“草稿待发布”与任务实际可执行
并存。该状态不是服务重启造成，也不存在已发布版本丢失。

本次已完成配置、运行门禁和页面语义三层闭环：五个 V1 全部校验发布；新任务必须冻结完整的
已发布且启用 Skill 集；管理页分别展示“内置执行器状态”和“DEV 运行绑定”，不再混为一个状态。

## 3. 新任务运行门禁

新增 `PublishedSkillSetGuard`，生产默认启用：

- 新任务创建前检查五项必需 Skill 是否已登记；
- 检查 DEV 是否存在生效绑定，且绑定版本状态为 `PUBLISHED`；
- 检查发布文档的 `skill_key` 与配置键一致；
- 检查 Skill 未被停用；
- 任一条件不满足时拒绝创建任务，不再静默走无版本内置能力；
- 已创建任务的冻结清单不变，继续按原兼容语义执行，不追溯打断。

Docker 环境显式设置 `ATLAS_REQUIRE_PUBLISHED_SKILLS=true`。自动化测试环境保留关闭开关，避免
与大量不关注配置发布的既有用例互相污染；新增独立集成测试在严格模式下验证未发布拒绝创建，
五项发布后创建成功并冻结五个 Skill 版本。

## 4. 页面调整

Skills 管理页现在同时展示：

- “执行器已内置”：说明后台代码能力已装载；
- “已发布生效/草稿待发布”：说明配置版本生命周期；
- “DEV 运行绑定 vN”：说明新任务实际冻结的版本；
- “当前查看版本”：避免查看新草稿时误以为线上生效版本被替换。

`PUBLISHED` 和连接测试 `PASSED` 状态改用正常态视觉，不再使用等待态颜色。
