# P2 旧评分模型逐项追溯矩阵

日期：2026-08-06  
范围：`RiskScoreService`、`RiskEnum`、`CompanyStandardService.updateRiskInfo` 与 Atlas V1 当前评分链路  
结论：P2 不把“代码已搬运”等同于“生产规则已执行”。当前真实口径为：**旧模型特征完整时按迁移规则重算；特征不完整时沿用 ES 快照中的物化旧模型分，再应用已确认事件最低分。**

## 1. 分数来源定义

| 页面名称 | 来源 | 用途 | 是否同一分数 |
|---|---|---|---|
| 输入旧报告分 | 上传 DOCX 解析结果 | 对比报告更新前后变化 | 否 |
| ES 物化旧模型分 | 企业快照中的旧系统结果 | 特征不完整时的安全基线 | 否 |
| 迁移规则计算分 | 新无副作用计算引擎 | 完整特征时重算；不完整时等于物化旧分 | 否 |
| 事件保底分 | 已确认且有证据的失联/欠薪/闭店事件 | 对规则分取最大值 | 否 |
| 系统原始分 | `max(迁移规则计算分, 事件保底分)` | 保留机器计算结果 | 否 |
| 当前人工分 | 运营调整后的分值 | 最终报告风险分 | 否；未调整时等于系统原始分 |

此前页面“旧系统分”没有区分输入 DOCX 与 ES 物化结果，P2 已拆分。

## 4. 页面与接口修正

- 任务工作台拆分六类核心分数及两类差异，明确每个来源。
- 规则评分页新增只读“旧评分模型执行与迁移追溯”，从后端真实追溯接口读取，不以静态假配置冒充执行逻辑。
- 规则表显示旧来源、新实现、迁移状态、是否可配置、真实执行条件和差异说明。
- 39项风险字典可展开逐项核对。
- 输入旧报告分由服务端实时解析任务绑定的DOCX；解析失败明确显示“未识别”，不会拿ES分替代。
- 执行模式不再通过“没有物化旧分命中”反向推断。只有存在完整规则必有的 `LEGACY_BASE_TOTAL` 命中才显示“完整迁移规则重算”；特征不完整且ES旧分为空时，明确显示“按0分基线计算，不代表旧模型已完整重算”。

## 6. P2.1后仍需业务或数据确认的规则

1. 朝阳12345减分服务的输入、公式和适用范围；
2. 关联企业分的来源范围、白名单与递归深度；
3. RiskEnum外16个活动标签未来由哪个正式字典维护，以及是否需要映射新的标准 `RiskType`；

分支/总部继承、空日期反向过滤和人工干预覆盖已分别按V1范围、工程纠错和既定审计原则处置，不再列为待确认项。以上四项仍会阻塞“全面启用完整迁移规则”。
