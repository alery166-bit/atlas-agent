# W11 多轮会话与运营门户实现记录

## 1. 本阶段目标

在 W10 确定性自然语言入口基础上，补齐持久会话、多轮槽位继承、旧报告真实上传和
运营人员可直接使用的完整页面，使任务不再依赖一次请求完成，也不因页面刷新而丢失。

## 2. 后端实现

新增 `agent_conversation` 与 `agent_message`，由 Flyway V8 管理。会话保存企业查询、
旧报告文件 ID、任务 ID、创建人和更新时间；消息保存严格递增序号、角色、解析意图、
缺失输入、建议动作和任务上下文。

新增接口：

```text
POST /api/agent/conversations
GET  /api/agent/conversations
GET  /api/agent/conversations/{conversationId}
GET  /api/agent/conversations/{conversationId}/messages
POST /api/agent/conversations/{conversationId}/messages
POST /api/files/previous-reports
```

多轮消息会继承已确认的企业、旧报告和任务槽位。相同幂等键重复提交时复用已生成的
助手消息，不会重复创建任务。会话只能由创建它的 `X-Operator-Id` 访问。

旧报告上传只接受有效 OOXML DOCX，限制 20 MB，服务端重新生成文件 ID 和存储名，
计算 SHA-256，不使用用户文件名拼接路径。

## 3. 前端实现

`atlas-console` 提供五个运营页面：

- 对话任务：会话列表、多轮消息、旧报告上传、任务卡片和结构化建议动作；
- 任务工作台：筛选任务、查看步骤/评分/门禁、处理证据、完成运营确认；
- 报告中心：查看版本、下载 DOCX、查看差异；
- 能力与数据源：展示当前 Skills、离线数据、搜索和 ES 状态；
- 系统设置：后端地址、运营身份、冰川运营/墨玉政企主题。

所有风险分、证据状态、门禁和下一步动作均来自后端，页面不复制业务规则。

## 4. 安全与边界

- 自由文本不能直接改分、确认/驳回证据或生成正式报告；
- 高影响动作仍走结构化端点和服务端门禁；
- 上传文件进行类型、签名、大小和路径安全校验；
- CORS 默认仅允许本地运营端；
- 当前 `X-Operator-Id` 是开发期身份占位，不等同生产认证。
