# 阶段一 P1～P2 实施记录

日期：2026-08-13

## 目标修正

Atlas 的 V1 主流程由“上传旧报告后更新”调整为“输入企业后直接排查并生成报告”。正式 DOCX
仍复用已经发布的 V1 模板，但业务内容来自本次任务冻结的企业数据、公开信息证据、评分结果和
运营确认，不再依赖某份旧企业报告。

## P1：取消旧报告依赖

- 新任务的 `previous_report_file_id` 改为可空，工作流从主体识别直接进入企业数据采集。
- Agent 只需完整企业名称或统一社会信用代码即可创建任务，页面不再要求上传旧报告。
- 报告生成器读取已发布正式模板作为版式基线；报告版本不再保存“被更新旧报告”的业务关系。
- 历史状态、字段和上传接口保留兼容读取能力，但上传接口在 OpenAPI 中标记为废弃，不进入当前流程。
- V16 放宽数据库历史字段；V17 将旧对话中的“还需要原报告”改为流程升级说明并清空过期输入要求。
- 数据源管理的“历史报告”改为“任务数据快照”。

验证结果：后端全量测试退出码 0，Flyway 17 个迁移在 H2 测试库通过；运营端生产构建通过，
16 项页面契约测试通过。V16 主版本已部署到 `10.210.0.62`，服务健康，线上不带旧报告创建任务
`AT-20260813-62A27C3D` 成功，返回待执行项仅为数据快照和评分。

## P2：企业查询与主体工作台

新增运营入口 `/companies`：

1. 输入企业名称或统一社会信用代码；
2. 调用当前企业主数据 Provider 的 `/api/companies/resolve`；
3. 区分唯一主体、多候选、未找到和查询失败；
4. 展示企业名称、信用代码、法定代表人、登记状态、地址、来源、数据时间和匹配度；
5. 选择主体后回到对话入口，并预填“排查某企业并生成风险报告”。

查询页只是主体确认台，不伪装成完整企业档案，也不把当前查询结果直接作为报告数据。正式发起任务
后，服务端仍会重新读取并冻结完整数据快照，以保证报告输入可追溯。

真实 ES 验证：北京简熹和食品有限公司为 `UNIQUE`，返回 1 个候选；来源为
`atlas-company-read`，信用代码、法人、存续状态、地址与 `data_as_of` 均可用。运营端 14 个路由
生产构建通过，17 项页面契约测试全部通过。
