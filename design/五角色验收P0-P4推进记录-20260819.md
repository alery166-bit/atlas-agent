## 2. P0：报告一致性

1. 当前正式报告同时校验主体/数据快照、评分快照、证据确认状态和运营确认。
2. 新评分、新证据或新主体冲突会使旧确认与旧报告失效；界面不再给出“下载正式报告”。
3. 单份历史报告仍可查阅，但下载接口拒绝把它作为当前正式结论交付。
4. 关键主体字段增加冲突识别，信用代码、法定代表人或登记状态不一致时进入人工核验。
5. 回归覆盖“更新评分—旧报告失效—重新确认—生成新报告—下载新版本”。

## 3. P1：证据与模型

1. Tavily 的展示摘要与 `raw_content` 分离，受控正文形成证据内容快照并保存哈希。
2. 自动确认必须存在可复核正文；只有标题/摘要而无正文的材料保留人工处理，不直接计分。
3. 模型非法 JSON 会进行一次只修复结构、不补充事实的重试；仍失败则安全降级并记录
   `atlas.model.invalid_json`。
4. 待处理页默认只展示待确认事项，已自动处理证据折叠显示。
5. 模型调用次数与 Prompt/Completion/Total Token 继续持久化并进入运行监控。

## 5. P3：报告与运营交付

1. 报告差异由元数据扩展为企业概况字段、工商/风险表行数、逐条规则命中和最终风险结论。
2. 调整前发现原实现直接更新评分快照，会让旧报告的历史分数一起变化。本轮改为每次人工调分创建
   新快照，V24 将同一输入的多次评分按时间追加保存，历史报告继续绑定原快照。
3. 运营手册已改为“输入企业—Agent 自动执行—仅异常人工—生成正式报告”，删除上传旧报告和
   逐步点击说明。
4. 连接器、规则、Skills 和模板状态统一为“草稿待发布、已校验待发布、已发布生效、历史版本”。
5. DOCX OOXML 结构测试通过；本机缺少 LibreOffice，自动逐页 PNG 渲染未执行，仍需 Word/WPS
   代表性报告人工签字。
