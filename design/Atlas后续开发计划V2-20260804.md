# Atlas 后续开发计划 V2

更新时间：2026-08-04

## 1. 重新定义“开发完成”

本计划继续严格限定在“单企业旧风险报告更新”V1，不扩展招商线索、批量监测、PDF和审批流。

V1 开发完成必须同时满足：

1. 运营人员通过页面上传一份真实旧报告并下达任务；
2. 系统完成主体识别、企业数据冻结、公开舆情检索和证据去重；
3. 运营人员完成证据确认/排除、风险计算、人工调整和最终确认；
4. 系统生成并下载可正常使用的新 DOCX，且新旧差异可查看；
5. 旧评分模型中纳入 V1 的规则已完成无副作用迁移，并通过历史样本回放；
6. 规则、搜索、数据源、Skills 和报告模板具备受控配置、版本发布和回滚能力；
7. 每个任务冻结实际使用的配置版本，历史结果不因后续配置变化而改变；
8. 运行监控和审计日志展示真实数据，而不是静态说明；
9. 查询失败停止、重试、备份和回滚经过实际演练。

## 2. 当前真实基线

### 已经完成

- 模块化单体、PostgreSQL、Flyway、Docker Compose 和线上体验环境；
- 单企业任务状态机、失败停止、重试、SSE 和操作工作台；
- ES 9.4.2 百企业验证环境及只读 Adapter；
- Tavily 真实搜索、企业身份词、主体门槛、证据去重和增量检索；
- 原始分、人工分、事件最低分、评分和报告快照；
- 旧 DOCX 解析、新 DOCX 生成、版本、差异和下载接口；
- 运营端完整导航和两套主题；
- 后端 71 项、运营端 4 项自动化测试。

### 尚未完成或容易被误认为已完成

- 旧 `RiskScoreService` 的细粒度计算规则尚未执行，当前线上是简化的 `RISK_RULES_V1`；
- 平台管理页面大多只展示运行状态，没有配置、发布和回滚能力；
- 审计日志页没有真实事件列表；
- 尚未用真实旧报告在服务器上完成一次从上传到 DOCX 下载的完整验收；
- 证据数量已增加，但排序、风险分类和误报控制仍需真实样本校准；
- 生产统一身份、生产 ES、安全、容量、备份恢复和回滚尚未验收。

## 3. 后续里程碑

### W19：真实业务闭环验收与缺陷清理

预计：3～5 人日

任务：

- 使用正式 V1 DOCX 在服务器上创建真实任务；
- 完成主体识别、证据处理、评分、人工调整、运营确认和报告下载；
- 检查新旧报告内容、样式、分页、空值和证据引用；
- 修正任务列表显示信用代码而非企业全称的问题；
- 清理或隔离历史乱码测试任务；
- 验证查询失败、报告失败和断点重试。

验收：

- 至少一份真实报告从上传到下载全链路成功；
- 任务列表、详情、证据、评分和报告中的企业名称一致；
- 无法完成的步骤给出可理解原因并可按规则重试；
- 不使用接口或数据库手工修改来绕过页面流程。

### W20：旧评分模型无副作用迁移

预计：8～12 人日

任务：

- 将 `RiskEnum` 与当前 `RiskType` 建立完整映射并标明启用范围；
- 从 `RiskScoreService` 抽取纯计算特征、规则、优先级和倍率；
- 将 `updateRiskInfo` 拆分为数据读取、特征构建、纯评分、持久化和外部副作用清单；
- 实现版本化 `LegacyRiskScoreEngineV1`，禁止直接查询 ES 或写回数据；
- 补齐行政处罚、经营异常、司法、工商变化、行业、投诉、舆情等纳入 V1 的特征；
- 保留失联/欠薪最低 6 分、闭店最低 8 分及人工分独立保存；
- 输出新旧规则命中和分数差异报告。

验收：

- 评分输入、规则命中、中间分、倍率和最终分均可解释；
- 同一冻结快照重复计算结果完全一致；
- 旧模型地区特例必须显式配置，不能隐藏在代码分支中；
- 相同输入下的差异要么一致，要么形成可审核的差异说明；
- 页面不再把简化评分误标为完整旧模型。

### W21：配置与版本管理底座

预计：4～6 人日

任务：

- 建立配置项、配置版本、发布记录、环境绑定和密钥引用模型；
- 建立“草稿—验证—发布—停用—回滚”状态机；
- 每个任务创建配置快照，记录规则、搜索、模型、数据源、Skill和模板版本；
- 配置变更写入真实审计事件；
- 明文密钥禁止通过浏览器读取或返回。

验收：

- 新配置发布后只影响新任务；
- 历史任务可定位并恢复其全部配置版本；
- 可回滚到上一发布版本；
- 并发发布和重复提交不会产生两个生效版本。

### W22：规则评分管理

预计：4～6 人日

任务：

- 风险标签、旧编号、分类、启停和证据要求管理；
- 事件最低分、等级阈值、时间窗口、权重和优先级配置；
- 规则草稿、回放测试、发布、变更对比和回滚；
- 规则被哪些任务使用的影响范围查询。

验收：

- 运营人员可以修改草稿，但不能直接修改生效版本；
- 未通过黄金样本回放的规则不能发布；
- 发布前能看到对历史样本的分数与等级影响；
- 任务评分快照保存准确规则版本。

### W23：数据源、搜索与模型管理

预计：5～7 人日

任务：

- 数据源新增、启停、连接测试、索引和字段映射；
- 必查/可选来源、失败停止、超时和重试策略配置；
- Tavily 深度、结果数、主题、查询模板和限流参数配置；
- 联网模型 Provider、模型名称、提示词、引用门槛和路由配置；
- 配置验证与脱敏运行状态。

验收：

- 错误连接或缺少必填参数的配置不能发布；
- 密钥只保存为服务器密钥引用；
- 数据源字段映射可以用样本记录预览验证；
- 搜索和模型失败不会被误记为零结果。

### W24：Skills 与报告模板管理

预计：5～7 人日

任务：

- 明确内置执行器和可配置 Skill 的边界；
- Skill 启停、输入输出约束、参数、依赖能力和版本发布；
- 报告模板上传、格式校验、字段映射、预览和版本发布；
- Skill、规则、数据源、模型和模板之间的依赖校验。

验收：

- 不修改代码即可调整查询策略、摘要提示词和模板版本；
- 核心执行器不能通过页面任意替换代码；
- 无效 DOCX、缺失字段或依赖未发布时禁止发布；
- 报告版本可追溯到具体模板和配置快照。

### W25：真实运行监控与审计日志

预计：4～6 人日

任务：

- 展示任务吞吐、耗时、失败步骤、搜索调用、模型调用和报告生成状态；
- 支持按任务、企业、操作人、事件类型和时间查询审计事件；
- 支持从失败任务下钻并按权限重试；
- 支持审计导出和配置版本变更对比。

验收：

- 页面数据来自真实任务、调用和审计表；
- 任一人工决定和配置发布都可定位操作人、时间、前后值和关联任务；
- 监控数据缺失时明确显示未知，不用固定“正常”占位；
- 重试不会重复生成证据、评分或报告版本。

### W26：黄金样本、舆情质量和运营验收

预计：8～12 人日

任务：

- 整理 20～50 份历史旧报告、人工修改终稿和关键证据；
- 标注企业身份词、证据归属、风险类型、原始分和人工分；
- 回放主体识别、搜索、去重、风险分类、评分和报告生成；
- 优化证据排序、权威来源、时效性、主体关联强度和误报控制；
- 由实际运营人员完成盲测并记录人工耗时和修改点。

验收：

- 严重主体错配为 0；
- 重大风险结论全部有可访问证据；
- 评分差异全部可解释并经业务确认；
- DOCX 核心字段和报告版本可追溯；
- Critical 和 High 缺陷清零后才能进入生产候选。

### W27：生产准备与发布候选

预计：5～8 人日

任务：

- 接入生产 ES、安全认证、TLS、索引别名和只读权限；
- 接入统一身份和最小权限；
- 完成容量、并发、超时、降级和依赖故障测试；
- 完成数据库、文件、配置和 ES 的备份恢复；
- 完成版本回滚和密钥轮换演练；
- 更新部署手册、运营手册、已知限制和验收报告。

验收：

- 查询失败停止规则覆盖率 100%；
- 备份恢复和应用回滚经过实际演练；
- 敏感配置不出现在页面、日志和报告中；
- 生产候选版本通过技术、产品和运营三方验收。

## 4. 发布节点与工作量

| 发布节点 | 包含范围 | 预计工作量 | 结果 |
|---|---|---:|---|
| R1 真实闭环版 | W19 | 3～5 人日 | 能通过页面完整生成一份真实报告 |
| R2 业务可试用版 | W20 | 累计 11～17 人日 | 旧评分核心规则真正进入新版引擎 |
| R3 可运营平台版 | W21～W25 | 累计 33～49 人日 | 平台管理从展示页变成可配置、可发布、可审计 |
| R4 生产候选版 | W26～W27 | 累计 46～69 人日 | 历史样本和生产环境通过验收 |

若由一名全栈研发连续推进，预计约 9～14 周；两名研发合理拆分后约 5～8 周。历史样本整理、
运营标注和生产环境准备可以并行，但不能用模拟结果替代验收。

## 5. 需要用户参与的时间点

- W19 结束：确认首份真实新报告内容是否达到业务可用；
- W20 中后段：当旧代码与现行业务口径冲突时确认采用哪一版规则；
- W22 发布前：确认可编辑规则的权限和发布责任；
- W26 开始前：提供或确认 20～50 份历史旧报告与人工终稿；
- W27 开始前：提供生产 ES、统一身份和生产密钥管理方式。

当前可以立即开始 W19，不需要等待新的环境或材料。
