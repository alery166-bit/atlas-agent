# W21 配置与版本管理底座实现记录

## 1. 结论

W21 已完成统一配置与版本管理底座。规则、搜索、模型、数据源、Skill、报告模板和通用配置
现在可以使用同一套“配置定义—不可变版本—环境绑定—发布记录—任务快照”模型管理。

本阶段完成的是后端底座和受控接口；各类配置的专用表单、预览和业务校验将在 W22～W24
逐项接入。现有管理页在专用编辑器接入前仍以状态展示为主，不将其误标为已经完成配置管理。

## 2. 数据模型

数据库迁移 `V10__add_configuration_version_management.sql` 新增：

- `configuration_definition`：配置项身份、分类、敏感标志和启停状态；
- `configuration_version`：不可变版本内容、校验结果、校验摘要和状态；
- `configuration_binding`：指定环境当前生效版本，使用行版本号避免并发覆盖；
- `configuration_release`：发布或回滚记录，并以请求幂等键阻止重复提交；
- `task_configuration_snapshot`：任务创建时冻结的配置清单。

配置分类覆盖：`RULES`、`SEARCH`、`MODEL`、`DATA_SOURCE`、`SKILL`、`REPORT_TEMPLATE`
和 `GENERAL`。

## 3. 状态与操作

配置版本采用以下受控流程：

1. 创建配置定义并生成首个 `DRAFT`；
2. 创建后续草稿，已发布版本不可直接修改；
3. 校验成功后进入 `VALIDATED`；
4. 只有已校验版本可以发布到指定环境并进入 `PUBLISHED`；
5. 新版本发布后，原生效版本转为 `INACTIVE`；
6. 回滚通过一次新的发布动作把历史版本重新绑定为当前版本，不篡改历史发布记录。

环境绑定只有一个当前版本。发布操作同时使用事务、绑定行版本和发布幂等键，重复请求不会生成
两个生效版本或重复发布记录。

## 4. 任务配置冻结

任务创建并保存后，系统立即冻结该环境当前全部配置。每条快照只保存：

- 配置键和分类；
- 实际使用的版本号、版本 ID 和内容校验和；
- 配置快照生成时间。

快照不复制配置正文或密钥。后续发布新版本只影响新任务；历史任务仍可通过版本 ID 和校验和
定位当时的完整配置，不会随环境当前配置变化。

## 5. 密钥与审计

- 敏感配置只接受服务端密钥引用，不允许通过浏览器保存明文密钥；
- 对 `apiKey`、`api_key`、`password`、`secret` 等明文字段进行拒绝校验；
- 管理接口不会返回 `secret_ref` 或密钥内容，只返回是否已配置；
- 创建配置、创建草稿、校验、发布和回滚均写入真实 `audit_event`；
- 审计记录包含操作人、动作、目标、内容摘要、时间和追踪标识。

## 6. 管理接口

统一入口为 `/api/platform/configurations`，已支持：

- 查询配置及各环境当前版本；
- 创建配置定义和首个草稿；
- 从已有配置创建新草稿；
- 校验版本；
- 发布到环境；
- 回滚到历史版本；
- 查询或补建指定任务的配置快照。

不存在的配置返回 404，版本或并发冲突返回 409，非法配置内容返回 400。

## 7. 验证结果

集成测试覆盖：

- Tavily 配置 V1 创建、校验和发布；
- 任务 1 冻结 V1；
- V2 发布后任务 2 冻结 V2，任务 1 仍保持 V1；
- 回滚 V1 及相同请求的幂等处理；
- 单环境只存在一个生效绑定；
- 敏感配置正文和密钥引用不出现在响应；
- 明文 API Key 被拒绝；
- 配置生命周期操作全部进入真实审计表。

最终结果：配置管理集成测试 2 项全部通过，后端 12 个模块构建成功。配置、任务和评分组合
回归测试共 13 项全部通过。
