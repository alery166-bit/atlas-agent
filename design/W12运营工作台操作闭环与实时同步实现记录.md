# W12 运营工作台操作闭环与实时同步实现记录

## 1. 本阶段目标

把 W11 已具备的完整运营门户从“可查看”推进到“可在一个页面完成处理”。运营人员不再
需要通过接口工具补做主体确认、评分、运营确认或报告生成，任务工作台直接按照服务端
`next_action` 给出当前唯一的受控操作。

## 2. 操作闭环

任务详情页已接入：

- 执行任务和失败任务重试；
- 企业主体候选加载及人工确认；
- 公开证据来源查看、确认和排除；
- 基于已确认公开证据计算风险分；
- 保留原始分的人工调分、原因分类和调分依据；
- 运营确认说明及确认提交；
- 报告生成、失败重试和已完成报告下载；
- 工作流步骤、重试次数、失败信息、门禁阻塞和下一步动作展示。

页面仅负责收集结构化操作参数。是否允许调分、确认或生成报告仍由后端状态机和门禁
判断，前端没有复制或绕过业务规则。

## 3. 实时同步

任务选中后，页面连接 `/api/tasks/{taskId}/events`，订阅服务端命名事件：

```text
task.status.changed
step.started
step.completed
step.failed
operator.action.required
data.snapshot.frozen
public.intelligence.collected
operator.confirmation.completed
report.generating
report.generated
report.failed
```

浏览器负责断线重连及 `Last-Event-ID` 恢复；页面对连续事件做短暂合并刷新，同时展示
“正在连接 / 实时同步 / 自动重连中”。所有人工操作成功后也会主动重载任务列表和工作区，
避免依赖事件到达时序。

## 4. 一致性修正

- 工作台风险等级展示改为与领域规则一致的 `[0,2)`、`[2,4)`、`[4,6)`、
  `[6,8)`、`[8,10]`；
- 阻塞原因使用后端实际枚举 `RISK_SCORE_NOT_FROM_LATEST_DATA` 和
  `UNVERIFIED_EVIDENCE`；
- 步骤名称覆盖 `VALIDATE_PREVIOUS_REPORT_REFERENCE`；
- 任务列表刷新后按任务 ID 保持当前选中项，不再意外跳回首条任务。
