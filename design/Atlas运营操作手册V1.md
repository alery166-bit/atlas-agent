# Atlas 单企业风险排查 Agent 运营操作手册 V1

## 1. 适用范围

V1 面向运营人员，使用平台已有企业数据直接完成单家企业风险排查并生成正式 DOCX。
不要求上传旧报告，也不以旧报告作为任务输入。批量排查、持续监测、招商线索报告、PDF
和跨部门风险处置不属于本版范围。

## 2. 发起任务

1. 打开“Atlas 工作台”，点击“新建对话”。
2. 输入企业完整登记名称或 18 位统一社会信用代码，例如“生成某某有限公司风险报告”。
3. Atlas 自动解析意图、匹配主体并启动任务，不需要逐步点击数据查询、公开信息检索、
   证据研判、评分和报告生成。
4. 主体唯一且数据、搜索、模型、规则与模板正常时，等待任务自动完成并下载正式报告。

企业名称存在歧义时，系统会转入“待处理”。运营人员必须核对信用代码、法定代表人、
登记状态和地址后确认主体，不能默认选择第一条候选。

## 3. 只处理 Atlas 无法判断的事项

“待处理”页面只汇集主体歧义、跨源数据冲突、来源正文不足、低置信度证据和失败重试。
Atlas 已自动确认或排除的证据默认收起，可在需要追溯时展开。

运营人员重点核对：

- 企业主档与最新工商变更是否冲突；
- 失联、拖欠工资、门店关闭等事实是否确属目标企业；
- 新闻、投诉或公告是否有可访问来源和可复核正文；
- 文章发布时间、事件发生时间和当前时效是否支持结论；
- 企业全称、已确认简称或品牌与风险主体的关系是否成立。

没有可访问来源或正文抓取失败的模型结论不得确认为风险证据。查询失败也不得写成
“无风险”或“暂未发现明确风险”，必须等待数据源恢复后重试。

## 4. 评分与人工调整

最终风险分由已发布的确定性规则计算；LLM 只做证据相关性、风险类型和摘要建议，不能
直接修改分数。系统保留规则原始分与人工调整分，并记录每条规则命中、引用和操作人。

如确有规则未覆盖的业务事实，可在任务详情中填写人工分、原因分类和具体依据。人工调整
不会覆盖原始分。当前评分数值和区间以“规则评分”页面的生效版本为准，本轮优化不调整
评分口径。

## 5. 正式报告与版本

Atlas 只有在以下条件同时满足时才生成正式报告：

1. 主体唯一，且关键主体数据不存在未处理冲突；
2. 必查企业数据和公开信息来源执行成功；
3. 所有证据已自动或人工完成处理；
4. 当前评分与确认记录匹配；
5. 当前模板、规则和任务冻结配置可用。

任何企业快照、证据决定、评分或确认变化都会使旧报告过期。过期报告只保留为历史版本，
不能继续通过“下载正式报告”交付。重新确认并生成后，报告库产生新版本，不覆盖旧文件。

“查看差异”按报告绑定的数据快照和评分快照比较版本信息、企业概况章节、表格行数、规则
命中和主要风险结论。

## 6. 失败与重试

- 主体不唯一：人工确认正确企业后继续。
- 企业数据、必查搜索来源失败：外部服务恢复后使用“重试任务”。
- 模型输出异常：系统自动进行一次 JSON 修复重试；仍失败的证据转人工，不污染任务状态。
- 证据正文无法取得：保留为待核验，不得自动确认。
- 报告生成失败：排除模板或存储问题后使用“重试报告”。
- 页面实时连接中断：等待自动重连，不要重复创建同一任务。

同一幂等键的重复提交不会创建第二个任务；不要通过连续点击绕过页面的进行中状态。

## 7. 日常验收与抽检

每天至少抽检自动完成和转人工任务各一部分，记录：主体误匹配、无来源风险、漏报、误报、
评分解释问题、报告版本不一致、版式问题、人工处理时长和 Token 用量。发现旧确认仍可下载
正式报告、无来源风险进入计分、数据源失败却输出无风险时，应按阻断性缺陷处理。

正式业务验收使用 20～50 家经业务负责人确认的黄金样本。历史 DOCX 只有在具备原始材料、
人工终稿、证据取舍、最终分数和标签后，才能登记为正式黄金样本。
