# Atlas 五角色验收后续工作计划

日期：2026-08-19  
依据：2026-08-18 研发、测试、产品、运营、售前五角色验收及 12 家企业真实试跑

## 一、验收后的统一结论

1. 当前版本可作为内部 V1，并可进入有边界的小范围业务试点。
2. 当前不满足“生产就绪”或“完整替代原风险监测平台”的承诺条件。
3. 单企业风险报告生产链路已经闭环，方向性替代程度约 78%；对原完整平台的替代程度约 40%。
4. 12 家真实试跑中 7 家自动完成、5 家转人工、0 家技术失败；但 7 家自动完成均为无公开证据任务，有公开证据的 5 家仍全部需要人工，说明自动化目前主要节省无异常任务和部分证据筛选工作。
5. 当前最高优先级不是继续扩展页面，而是保证“数据、证据、评分、确认、报告”始终属于同一版本，避免过期报告被当作最新正式结论。
6. 用户已决定暂不调整评分数值，因此评分规则扩展保留为业务决策门，不在未经确认时发布。

## 二、工作原则

- 先正确，再自动；先单企业报告闭环，再扩展完整监测平台。
- 正式报告必须可追溯到确定的数据快照、证据决定、评分版本、人工确认和模板版本。
- 数据源失败、主体冲突、证据无来源或结论过期时，系统不得输出“无风险”或提供正式报告下载。
- LLM 只做证据理解、分类和摘要建议，不直接修改风险分；最终分数仍由确定性规则计算。
- 自动化率按“无公开证据任务”和“存在公开证据任务”分开统计，避免用总体自动完成率掩盖证据研判能力不足。

## 三、分阶段计划

### P0：正式报告一致性与错误交付阻断（第 1～2 个工作日）

目标：任何评分、证据、主体或配置发生变化后，旧报告不得继续被标记为最新正式结论。

| 编号 | 工作项 | 主要改造 | 验收标准 |
|---|---|---|---|
| P0-1 | 评分—确认—报告版本一致性 | 新评分或证据变化后自动使旧确认和旧报告失效；修正 `next_action`；下载接口只返回当前有效正式报告 | `confirmation_state=STALE` 时不可出现“下载正式报告”；旧报告保留为历史版本但明确标记过期 |
| P0-2 | 报告生成门禁 | 报告绑定主体快照、证据集、评分快照、确认记录、规则、模型和模板版本 | 任一依赖版本变化后必须重新确认并生成新报告 |
| P0-3 | 跨源与跨时间冲突提示 | 对法定代表人、工商状态、统一信用代码等关键字段增加冲突识别和待核验状态 | 已知“任志远/陆小安”场景能够提示冲突，系统不得静默选取旧值 |
| P0-4 | 回归与线上复验 | 增加状态机、下载门禁、并发更新和历史版本测试 | 自动化回归通过；线上构造“评分更新—旧确认失效—重新确认—新报告”全链路通过 |

阶段出口：北京互联港湾任务的评分、确认和报告不一致问题关闭；不存在可下载的过期“正式报告”。

### P1：证据可复核与 Agent 自动研判质量（第 3～6 个工作日）

目标：每条风险结论都有可复核来源，真正不确定的事项才交给运营人员。

| 编号 | 工作项 | 主要改造 | 验收标准 |
|---|---|---|---|
| P1-1 | 公开证据快照 | 保存标题、URL、来源、发布时间、抓取时间、正文摘录或受控正文、内容哈希 | 已确认风险证据的可复核字段完整率 100%；网页变化后仍能解释当时结论 |
| P1-2 | 无来源结论阻断 | 模型声称有风险但无法给出来源时自动排除或转人工，不进入计分 | 所有进入报告的公开风险事项均可定位到证据记录 |
| P1-3 | 模型结构化输出加固 | JSON Schema 校验、修复重试、失败降级、调用版本与 Token 留痕 | 非法 JSON 不污染任务状态；失败可重试且不会重复确认或重复计费 |
| P1-4 | 待处理页面减负 | 自动确认和自动排除默认折叠，只展开主体歧义、低置信度、来源不足和冲突证据 | 运营人员默认只看到真正需要判断的事项 |
| P1-5 | 分层质量指标 | 分开统计无公开证据任务自动完成率、公开证据自动决定率、转人工原因 | 运行监控可直接看到各类自动化效果，而非只有总体完成率 |

阶段出口：证据链完整、模型失败可恢复、人工队列只包含无法自动判断的事项。

### P2：业务验收基线与评分决策门（第 2 周，依赖业务材料）

目标：从“系统能运行”升级为“业务结论经过样本证明”。

| 编号 | 工作项 | 主要改造 | 验收标准 |
|---|---|---|---|
| P2-1 | 黄金样本集 | 整理 20～50 家历史原始材料、人工最终报告及关键结论，覆盖有风险和排查后无明确风险企业 | 每个样本有主体、证据取舍、最终分数、标签和报告预期；业务负责人确认 |
| P2-2 | 规则缺口决策 | 形成吊销、注销、破产、行政处罚、严重违法等事项的评分建议和影响样本 | 仅形成建议、差异和回放结果；用户确认前不发布新分值 |
| P2-3 | 黄金样本回放 | 固定 ES、搜索、模型、规则和模板版本，对黄金样本批量回放 | 主体匹配、证据取舍、分数、标签、报告内容逐项给出通过率和差异 |
| P2-4 | 12 家试跑复验 | 在 P0、P1 完成后重跑现有 12 家企业 | 0 技术失败、0 过期正式报告、0 无来源风险结论；自动化指标可分层解释 |

阶段出口：形成可签字的 V1 业务验收基线。若评分规则继续暂缓，可完成证据和报告验收，但不得宣称评分业务口径已正式验收。

### P3：报告与运营交付质量（第 2 周）

目标：正式 DOCX 可读、可对比，操作说明与实际流程一致。

| 编号 | 工作项 | 主要改造 | 验收标准 |
|---|---|---|---|
| P3-1 | 正文级报告差异 | 在现有版本、日期、分数和数量差异基础上，增加章节、表格行和主要结论差异 | 运营人员能够直接看到新增、删除和修改内容 |
| P3-2 | DOCX 视觉回归 | 固定代表性企业，执行 Word/WPS 逐页检查或自动渲染比对 | 无异常空行、表格截断、缩进错位、跨页表头丢失和模板残留 |
| P3-3 | 运营手册更新 | 删除上传旧报告和逐步点击的旧流程，改为“输入企业—Agent 自动执行—异常人工—正式报告” | 手册、页面和实际行为一致，新运营人员可独立完成任务 |
| P3-4 | 配置状态收口 | ES、规则、模板、Skills 明确显示“内置默认”“已发布”或“待发布”，消除草稿与实际运行不一致 | 页面展示状态与新任务冻结配置完全一致，不再出现伪配置 |

阶段出口：报告质量和运营流程通过人工签字验收，管理页面不再产生配置误解。

### P4：生产安全与运维准备（第 3 周）

目标：从当前 DEV/试点环境升级到可控的生产部署条件。

| 编号 | 工作项 | 主要改造 | 验收标准 |
|---|---|---|---|
| P4-1 | 统一身份与权限 | 接入统一身份，至少区分运营人员和系统管理员；服务端强制鉴权 | 匿名访问业务接口失败；越权测试通过；操作人不可由客户端伪造 |
| P4-2 | 网络与密钥安全 | HTTPS、ES 鉴权、密钥托管、数据库和 ES 最小暴露面 | 密钥不进入前端、日志和镜像；生产 ES 不允许匿名访问 |
| P4-3 | 数据出域与来源合规 | 明确发送给 Tavily、百炼的数据范围、保存周期、来源许可与脱敏边界 | 形成批准记录；接口和日志符合批准范围 |
| P4-4 | 容量与稳定性 | 并发任务、搜索/模型限流、Token 成本、超时、恢复和幂等压测 | 达到约定并发和日任务量；重复提交不产生重复外部调用或重复收费 |
| P4-5 | 生产备份、回滚和恢复 | 复用已通过的 DEV 备份恢复能力，补生产配置、应用回滚、ES 备份和故障演练 | 数据库、报告、配置和 ES 均可恢复；应用版本可回滚；演练有记录 |
| P4-6 | 监控告警 | 增加服务、数据源、队列、模型、报告、成本和数据一致性告警 | P0 错误、任务停滞、外部服务异常能主动告警并定位 |

阶段出口：安全、容量、恢复和运维验收通过后，才允许使用“生产就绪”表述。

### P5：受控业务试点（建议连续 2 周）

目标：用真实运营结果验证准确性、效率和成本，而不是只看自动化测试。

试点范围建议为 50～100 家企业，保留人工抽检。每日记录以下指标：

- 主体误匹配数，目标为 0；
- 评分、确认、报告版本不一致数，目标为 0；
- 无来源风险进入正式报告数，目标为 0；
- 技术任务成功率和报告生成成功率；
- 无公开证据任务自动完成率；
- 有公开证据任务自动决定率及转人工原因；
- 运营单家平均处理时长和人工处理证据数；
- 搜索、模型调用次数及单任务 Token/费用；
- 黄金样本一致率、抽检漏报和误报情况。

阶段出口：产品、研发、测试、运营、售前共同签署试点结论，决定正式上线、继续优化或缩小范围。

### P6：替代原系统的中期路线（V1 上线后）

这部分不纳入当前 V1 上线门槛，按业务价值另行立项：

1. 批量企业排查与名单导入；
2. 重点企业持续监测、增量事件和主动预警；
3. 风险动态、关注名单、趋势分析和专题报告；
4. 组织、角色、部门协同和处置闭环；
5. 约 60 类风险标签的完整业务口径与可见偏好；
6. 月报、区域/行业风险指数和管理驾驶舱；
7. 招商线索报告及企业资产能力复用。

## 四、推荐执行顺序

```text
P0 一致性阻断
  → P1 证据与自动研判
  → P2 黄金样本与业务决策门
  → P3 报告和运营交付
  → P4 生产安全与运维
  → P5 两周受控试点
  → P6 原系统替代扩展
```

P0 与 P1 必须最先完成。P2 的样本整理可与 P1 并行准备；P3 可在 P2 回放期间推进；P4 不应等待所有业务优化结束，但必须在正式生产试点前完成。

## 五、需要用户确认或提供的事项

执行中只在以下节点停下来确认：

1. 黄金样本是否具备人工最终版和明确的证据取舍；
2. 是否启动吊销、注销、破产、行政处罚、严重违法等评分规则调整；
3. 生产统一身份、域名/证书、ES 与部署环境信息；
4. Tavily、百炼数据出域及来源使用边界；
5. 试点企业清单、抽检负责人和正式通过标准。

## 六、里程碑

| 里程碑 | 预计完成 | 可承诺状态 |
|---|---|---|
| M1：P0 关闭 | 2 个工作日 | 内部 V1 不会错误交付过期正式报告 |
| M2：P1+P3 关闭 | 1～2 周 | 可演示、可运营、证据可复核的单企业报告 Agent |
| M3：P2 关闭 | 约 2 周，取决于样本和规则确认 | 业务验收基线明确，可进入正式试点 |
| M4：P4 关闭 | 约 3 周 | 具备生产试点条件 |
| M5：P5 关闭 | 连续 2 周试点后 | 决定是否正式上线单企业风险报告能力 |

以上工期按当前单线开发估算；若业务样本、身份系统或生产基础设施未就绪，对应里程碑顺延，但不影响前置代码和测试工作继续推进。
