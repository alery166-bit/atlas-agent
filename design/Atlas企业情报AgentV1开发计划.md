# Atlas 企业情报 Agent V1 开发计划

> 目标：完成“单企业旧风险报告更新”第一条生产链路  
> 计划基线：详细设计 V1.2  
> 暂不包含：生产 ES 迁移、招商线索、批量任务、PDF、审核审批、微服务拆分

## 1. 最终交付

运营人员可以在对话框输入企业和要求、上传旧报告，系统使用离线企业数据完成主体识别、工商与风险核验、公开舆情调查、风险评分和证据整理；运营人员确认或改分后，生成新版正式 DOCX，并可追溯数据快照、原始分、人工分、证据、规则和报告版本。

## 2. 实施原则

1. 先搭模块化单体，不拆微服务；
2. 先用 H2、本地文件、JSON/CSV 跑通，ES 后接；
3. 一个 Agent 负责理解和文字工作，固定工作流负责业务步骤；
4. 每周都交付可运行的纵向结果；
5. 外部搜索或 ES 没有真实环境时标记“未联调”，不能用模拟结果替代；
6. 范围变更必须单独评审。

## 3. 里程碑计划

### M1：工程和契约基线（W1）

任务：

- 创建 Maven 多模块工程；
- 锁定 JDK、Spring Boot、数据库访问和 DOCX 库版本；
- 建立领域、应用、适配器、API、Worker 和启动模块；
- 建立统一响应、错误码、Trace、审计基础；
- 将核心表落实为 Flyway DDL；
- 建立 H2 local Profile 和本地文件存储；
- 形成 OpenAPI V1；
- 实现任务创建、任务查询和 SSE 心跳；
- 配置基础 CI、单元测试和代码规范。

交付：

- 可启动的后端；
- 数据库 V1 迁移；
- OpenAPI 文件；
- 第一版任务表和审计表；
- 开发启动说明。

验收：

- 无 ES、无搜索凭据、无 Docker 时可以启动；
- 能创建任务并在页面或 API 中看到状态；
- 重复 `Idempotency-Key` 不创建重复任务；
- H2 数据重启后不丢失。

### M2：任务工作流和离线企业数据（W2）

任务：

- 实现 V1 状态机；
- 实现步骤记录、租约、重试和断点续跑；
- 建立 `CompanyDataProvider`；
- 实现 JSON 和 CSV Provider；
- 建立企业身份绑定；
- 将企业主档、工商变化和风险事件转为标准快照；
- 建立固定测试 fixture 和高覆盖企业样本；
- 实现必查来源失败停止。

交付：

- 企业主体识别接口；
- 企业事实和风险事件快照；
- 任务步骤进度事件；
- 来源状态和错误详情；
- 第一批自动化场景测试。

验收：

- 北京简熹和食品有限公司可以形成冻结快照；
- 高事件量企业不会把全部 CSV 载入内存；
- 多候选主体必须等待人工；
- 查询失败不进入评分；
- 查询成功但 0 条被正确记录。

### M3：风险评分和运营处理（W3）

任务：

- 建立 `RiskScoreEngine` 和输入输出契约；
- 迁移 `RiskEnum`；
- 隔离 `RiskScoreService` 纯计算逻辑；
- 梳理 `updateRiskInfo` 的读取、计算和副作用；
- 实现失联、欠薪、闭店最低分；
- 保存命中规则和规则版本；
- 实现原始分、人工分和人工调整；
- 实现待办处理接口和页面基础组件。

交付：

- 可重复的评分快照；
- 新旧评分对照结果；
- 人工调整记录；
- 评分解释视图。

验收：

- 失联、欠薪最低 6 分，闭店最低 8 分；
- 同时命中多个最低分规则取最大值，不相加；
- 同快照重复计算结果一致；
- 人工分不覆盖原始分；
- 每次改分包含原因、操作者和时间。

### M4：旧报告和 DOCX 生成（W4）

前置业务输入：

- 正式模板字段映射；
- 空值、动态表格和可继承章节规则；
- 人工分低于事件最低分的最终处理。

任务：

- 解析旧 DOCX；
- 提取旧报告日期、企业信息、旧分数和主要结论；
- 实现模板字段填充；
- 实现动态风险和证据表格；
- 实现受控文字段落；
- 实现报告输入哈希和版本；
- 实现报告下载和差异；
- 建立 DOCX 渲染和视觉检查流程。

交付：

- 旧报告解析结果；
- 新版 DOCX；
- 报告版本和差异；
- 报告失败重试。

验收：

- 北京简熹和食品完成第一份端到端新版报告；
- Word 可以正常打开；
- 页眉、页脚、样式和分页可接受；
- 无残留占位符；
- 重大结论全部绑定证据；
- 相同输入不重复生成版本。

### M5：公开舆情和证据（W5）

前置外部输入：

- 至少一个主流搜索服务方案；
- 至少一个带联网检索的大模型方案；
- 外部模型数据分级矩阵；
- 搜索凭据和使用边界。

任务：

- 建立 `PublicSearchProvider`；
- 实现模拟 Provider 和真实 Provider 适配；
- 生成企业名称、品牌、门店和重点风险查询词；
- 实现 URL、内容哈希和语义去重；
- 实现主体匹配；
- 提取失联、欠薪和闭店候选；
- 实现证据确认、驳回和补充；
- 保存查询词、提供方、时间、排名和引用。

交付：

- 多提供方搜索编排；
- 公开证据清单；
- 三类重点风险候选；
- 搜索失败与 0 条结果区分。

验收：

- 没有原始引用的大模型答案不能触发最低分；
- 品牌、加盟店和同名企业不会直接归属；
- 必查搜索失败进入 `SOURCE_FAILED`；
- 证据可追溯到查询和来源。

### M6：Agent、UI 和端到端集成（W6）

任务：

- 实现任务参数结构化提取；
- 实现搜索词和受控摘要能力；
- 将 Agent 接入固定工作流；
- 接入对话入口、任务进度、待办处理、企业档案和报告中心；
- 完成 SSE 重连和状态恢复；
- 接入冰川运营、墨玉政企主题；
- 实现权限和联系方式脱敏；
- 完成关键运行指标。

交付：

- 完整对话式任务入口；
- 实时任务卡片；
- 运营处理工作台；
- 报告查看和下载；
- 两套视觉主题。

验收：

- 对话可以创建真实任务；
- Agent 无法跳过必查步骤或自行改分；
- 页面刷新后任务不丢失；
- 失败步骤可以恢复；
- 风险运营人员可以独立完成一份报告。

### M7：回归、运营走查和试运行（W7）

任务：

- 扩充黄金样本；
- 完成主体、评分、舆情、报告回归；
- 完成文件上传、路径、权限和数据泄漏测试；
- 完成 Worker 接管、重复提交和 SSE 重连测试；
- 完成运营端到端走查；
- 修复 Critical 和 High 缺陷；
- 编写部署、备份、恢复和运维说明。

交付：

- 验收报告；
- 已知限制清单；
- 操作手册；
- 部署运行手册；
- 试运行版本。

验收：

- Critical 缺陷为 0；
- 严重主体错配为 0；
- 评分确定性 100%；
- 重大结论证据覆盖率 100%；
- 查询失败停止规则覆盖率 100%；
- DOCX 核心字段正确率 100%；
- 运营人员完成并确认端到端任务。

## 5. 人员与周期假设

建议最小配置：

- 后端/架构 1～2 人；
- 前端 1 人；
- Agent/搜索/数据 1 人，可由后端兼任；
- 测试 1 人；
- 风险运营代表持续参与；
- 产品负责人负责范围和规则确认。

在上述配置下，计划为约 7 周。若只有 1 名全栈研发，预计需要 10～14 周；若 DOCX 映射、搜索凭据或历史样本延迟，对应里程碑顺延，但不应把招商、PDF 或 ES 迁移插入空档。

## 6. ES 后续独立里程碑

获得 ES 服务器环境后再启动：

1. 确认 ES 版本、认证、TLS、索引和网络；
2. 实现 `EsCompanyDataProvider`；
3. 用离线 Provider 与 ES Provider 做同企业结果对照；
4. 执行模板、Bulk、routing、分页和性能验证；
5. 切换生产 Profile；
6. 保留离线 Provider 作为回归与应急工具。

该里程碑不改变任务、评分、证据和报告领域模型。
