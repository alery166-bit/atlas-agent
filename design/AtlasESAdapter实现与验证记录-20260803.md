# Atlas ES Adapter 实现与验证记录

验证日期：2026-08-03

## 1. 结论

后端 `atlas-adapter-es` 已从空模块实现为可配置的企业数据 Provider，并部署到
`10.210.0.62`。远端服务当前通过 Compose 内部网络访问 ES 9.4.2，三家指定企业均通过
主体精确解析和数据快照验证。ES 查询阶段没有失败，现阶段流程的外部阻塞项是尚未配置
真实搜索引擎和联网模型检索参数。

## 2. 实现范围

- 企业名称或统一社会信用代码精确解析；
- 企业主档加载；
- 工商变更事件加载；
- 风险相关事件加载；
- 联系方式数量、类型和脱敏值聚合；
- 已入库公开舆情数量、最新时间和近期摘要聚合；
- 基于 `atlas_company_id` 的子索引 routing 查询；
- Basic Auth、API Key、超时、别名和最大返回数配置；
- ES 非 2xx、网络错误或必需子查询失败时返回结构化失败，不重试、不降级伪造数据；
- `offline` / `es` 两种数据模式通过配置切换。

关系和资产索引暂时为空，也没有进入 V1 风险报告更新所需的查询合同，因此本次不读取。

## 3. 自动化验证

## 5. 外部检索边界

另使用北京简熹和食品任务 `b0430ac6-8ab9-4d28-b3e0-858a71dac439` 验证失败语义：

- ES 主体、主档和子索引查询全部成功；
- 进入公开检索后，因 live provider 未配置，任务停止为 `SOURCE_FAILED`；
- 错误码为 `SEARCH_PROVIDER_UNAVAILABLE`；
- 检索批次记录的细分错误为 `SEARCH_PROVIDER_NOT_CONFIGURED`；
- 系统没有以空结果、fixture 或模型猜测替代真实查询。

该行为符合已确认的“查询失败暂时停止”规则。要完成真实报告全链路验收，需要提供至少一个
必需的主流搜索服务参数；联网模型检索可作为第二提供方接入。
