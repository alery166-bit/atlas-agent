# Atlas 自动研判闭环程序优化记录

日期：2026-08-14

## 1. 本轮目标

将 Atlas 从“模型给建议、运营逐条点击、再人工触发评分与报告”的辅助工具，调整为默认能够独立完成单企业风险排查报告的 Agent：

1. 自动获取企业数据和公开信息；
2. 自动调用联网模型理解证据；
3. 对满足安全条件的证据自动确认或排除；
4. 只把歧义、低置信度、主体冲突或模型失败交给人工；
5. 按确定性规则计算风险分；
6. 自动生成正式 DOCX；
7. 全程保留证据、模型判断、规则命中、人工处理和模型用量。

本轮不包含 UI 风格重做、招商线索、多企业批量、PDF、生产 ES 高可用和复杂权限体系。

## 2. 优化后的主流程

```text
运营人员输入企业任务
        ↓
主体识别与企业数据快照
        ↓
Tavily 公开信息检索与正文采集
        ↓
百炼模型进行主体匹配、相关性、风险类型和置信度判断
        ↓
安全策略自动确认 / 自动排除
        ├─ 存在歧义、低置信度、主体冲突、线索级材料 → 待人工异常
        └─ 全部可自动处理 → 继续
        ↓
确定性评分引擎计算原始分、事件最低分和风险等级
        ↓
Atlas 系统确认
        ↓
自动生成 DOCX 报告
```

人工不再是正常流程中的必经步骤，而是异常分支。

## 3. 自动证据决策边界

| 模型结论与证据条件 | Atlas 动作 |
| --- | --- |
| 高置信度“不相关” | 自动排除 |
| 高置信度“相关”，主体匹配，风险类型明确，具有可追溯来源，材料不是仅线索级 | 自动确认，并采用模型识别出的风险类型 |
| 置信度低于阈值 | 转人工处理 |
| 主体不确定或冲突 | 转人工处理 |
| 风险类型为 `OTHER`、理由或摘要缺失 | 转人工处理 |
| 仅为搜索线索、正文不足 | 转人工处理 |
| 模型不可用、调用失败或部分失败 | 停止自动完成，保留重试与人工处理入口 |
| 必查数据源失败 | 任务停止，不允许把失败误判为“无风险” |

默认自动决策已启用，默认置信度阈值为 `0.90`；后台允许以受控配置调整，合法范围为 `0.80～1.00`。

## 4. 评分语义修正

### 4.1 数据入口统一

- ES 物化旧分同时兼容 `riskScore` 和 `legacyScore`；
- ES 旧标签同时兼容 `riskLabels` 和 `legacyLabels`；
- 评分仍保留旧模型物化分、迁移规则分、事件最低分、系统原始分和人工分的完整解释链。

### 4.2 结构化事件直接触发最低分

在规则时间窗口内，ES 结构化数据中的以下事实不再依赖网络舆情或人工二次确认才能进入最低分：

| 风险事实 | 最低分 |
| --- | ---: |
| 失联 | 6 |
| 欠薪 | 6 |
| 闭店 | 8 |

公开证据和结构化事件按风险类型合并、去重并保留引用。最终评分仍由确定性规则引擎完成，模型不能直接覆盖业务分数。

风险等级边界保持：高风险 `[10,8]`、中高风险 `(8,6]`、中风险 `(6,4]`、中低风险 `(4,2]`、低风险 `(2,0]`。

## 5. 报告生成与表达

- 自动流程完成后直接生成正式 DOCX，不再要求运营人员逐步点击；
- 报告中的证据确认用语统一为“经研判确认”，不再错误暗示所有结果都经过人工；
- 报告同时支持 Atlas 自动研判和必要时的人工复核；
- 网络舆情继续使用序号、事项、发布时间、摘要和来源五列表格；
- 无数据章节继续使用约定的无数据说明，表格中的缺失字段继续使用 `/`；
- 任务重复触发时沿用幂等报告生成机制，避免无意义地产生相同版本。

## 6. 模型用量与审计

新增语义研判作业级用量字段：

- 模型调用次数；
- 输入 Token；
- 输出 Token；
- 总 Token；
- 实际服务商与模型；
- 每批模型判断结果及关联证据。

数据库迁移升级至 V20。运行监控能够汇总模型调用次数和 Token，任务工作台能够展示单次作业的服务商、模型和用量；服务商没有返回用量时明确显示为未返回，不伪造估算值。

Atlas 自动完成产生的证据决定和任务确认，在审计中标记为 `AGENT`，与人工操作区分。

## 7. 故障与恢复

- 语义研判作业保持单任务幂等启动；
- 已完成批次持久化，只补跑未完成证据；
- 支持取消、失败说明和显式重试；
- 模型不确定不会被当成无风险，而是形成待人工异常；
- 必查源失败会停止任务；
- 自动评分、确认和报告生成继续使用现有幂等边界；
- 服务重启后的运行中作业按既有恢复策略转为可诊断失败，避免任务静默悬挂。

## 8. 验证范围

本地验证覆盖：

- 自动证据确认、自动排除和人工异常分流；
- 自动评分、系统确认和 DOCX 生成；
- ES 旧分字段兼容；
- 结构化失联、欠薪、闭店最低分；
- 风险等级边界；
- 报告文字和幂等更新；
- 模型调用与 Token 持久化、接口和运行监控；
- 数据库 V1～V20 全量迁移；
- 运营端生产构建与页面契约测试。

本记录不把以下内容声明为已验收：

- `10.210.0.62` 的本轮部署；
- 生产 ES 数据上的回归；
- 百炼真实调用和账单消耗；
- 新生成 DOCX 的 Word/WPS 逐页主观验收。

这些动作涉及真实环境和外部模型调用，需要在获得用户确认后执行。

## 9. 当前结论

代码层已经从“模型辅助、人工必经”调整为“Atlas 默认自主完成、人工只处理异常”。LLM 的职责是理解意图和证据，规则引擎负责可复现评分，报告渲染器负责确定性输出，运行监控负责证明模型是否真实调用以及消耗多少。

进入真实环境后，首轮验收应选择至少一家具备工商、处罚或诉讼等结构化风险数据，同时能够检索到公开舆情的企业，核对四个结果：主体是否正确、自动证据决策是否合理、风险分是否可解释、DOCX 是否可直接交付。
