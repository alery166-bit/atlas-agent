# 模型辅助研判后台作业实施记录

日期：2026-08-07  
范围：第一阶段“模型辅助研判收口”中的后台执行、进度、取消、续跑和故障留痕。

## 实施结论

模型辅助研判已从同步 HTTP 长等待改为持久化后台作业。启动接口立即返回 `202`，运营端可继续浏览和处理
其他信息；任务页每 2 秒读取作业进度，展示待执行、执行中、部分失败、完成、失败和已取消状态。

安全边界没有改变：模型结果只写入证据元数据，证据仍保持 `UNVERIFIED`，不会自动确认、驳回、计算风险
分或修改人工分。

## 后端实现

- 新增 V14 `evidence_semantic_review_job`，持久化任务、状态、总数、已处理数、成功数、失败数、模型、错误、
  取消标记及起止时间；同一任务只允许一个活动作业。
- 新增独立模型研判线程池，默认并发数为 1，可通过 `ATLAS_MODEL_REVIEW_CONCURRENCY` 调整。
- 支持幂等启动：重复点击返回当前活动作业，不重复调用模型。
- 每批 3 条证据执行后立即保存成功建议并更新进度；失败批次不会回滚此前成功结果。
- 支持取消：当前 HTTP 模型批次完成后停止；已经保存的模型建议不删除。
- 服务重启会把未完成作业明确标记为失败并提示重新补跑，不把失联线程伪装成运行中。
- 再次启动仍只选择没有 `llm_reviewed_at` 的未确认候选，构成续跑闭环。

## 接口和页面

- `POST /api/tasks/{taskId}/public-intelligence/evidence/model-review`：启动或返回活动作业；
- `GET /api/tasks/{taskId}/public-intelligence/evidence/model-review/jobs/latest`：读取最近作业和实时进度；
- `POST /api/tasks/{taskId}/public-intelligence/evidence/model-review/jobs/{reviewJobId}/cancel`：请求取消；
- 任务页增加进度条、成功/失败计数、错误说明、取消入口和“继续补跑”入口。
