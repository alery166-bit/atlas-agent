# W6 搜索接入与报告证据落版实现记录

## 1. 目标与范围

W6 在不依赖 ES 环境的前提下，把 W5 的公开检索契约补齐为可接真实服务的
HTTP 适配层，并把人工确认的公开证据写入正式 V1 DOCX。

本轮包含：

- 多搜索 Provider 配置、密钥和启动校验；
- 标准 HTTP 搜索适配器；
- 网页正文安全抓取、文本提取和不可变快照；
- 已确认证据进入报告摘要、风险标签和舆情投诉章节；
- 证据内容进入报告幂等哈希；
- 迁移脚本、接口契约和端到端测试。

本轮不包含：

- 购买或绑定具体搜索引擎、联网模型账号；
- 绕过验证码、登录墙、付费墙或网站反爬策略；
- ES 数据迁移；
- PDF 输出；
- 审核工作流。

## 2. 搜索 Provider

`atlas.intelligence.search.providers` 支持多个 Provider，每个 Provider 可配置：

- `name`、`enabled`、`mode`；
- `base-url`、`path`；
- 查询和条数参数名；
- 最大结果数；
- 连接和请求超时；
- 最小请求间隔；
- 是否为必选来源；
- 是否提供可访问引用；
- API Key 请求头和前缀。

启用且要求密钥的 Provider 缺少密钥时，应用启动失败。禁用 Provider 不强制
校验密钥，保证默认离线开发环境可启动。

标准 HTTP 返回契约为：

```json
{
  "results": [
    {
      "id": "source-result-id",
      "title": "标题",
      "url": "https://example.com/article",
      "snippet": "摘要",
      "published_at": "2026-07-30T00:00:00Z",
      "rank": 1,
      "metadata": {}
    }
  ]
}
```

401/403、429、5xx、超时、连接失败和非法响应均转换为明确失败批次，不伪造
成功结果。

## 3. 网页正文快照

新增 `evidence_content_snapshot` 表和 V6 Flyway 迁移，保存：

- 请求 URL、最终 URL、HTTP 状态和内容类型；
- 原始内容、提取文本；
- 原始内容哈希、提取文本哈希；
- 字节数、是否截断；
- 失败代码、失败说明和抓取时间。

安全约束：

- 仅允许 HTTP/HTTPS；
- 默认拒绝回环、链路本地、站点本地、组播和解析到内网的地址；
- 不自动跟随重定向；
- 限制连接/请求超时和最大响应体；
- 只接受 HTML、XHTML 和纯文本；
- 抓取失败仍保存失败记录；成功快照幂等复用，失败快照可重试。

## 4. 报告落版规则

只有 `verification_status=CONFIRMED` 的公开证据进入报告。

内容优先级：

1. 同一证据最新的 `CAPTURED` 正文快照；
2. 搜索结果摘要。

章节映射：

- `WAGE_ARREARS` → “互联网投诉”；
- `OUT_OF_CONTACT`、`STORE_CLOSURE`、`OTHER` → “网络舆情”。

每条报告证据保留：

- 风险类型和标题；
- 正文摘要或检索摘要；
- 来源域名/Provider；
- 发布时间；
- 抓取时间；
- 原文 URL；
- 内容是否被截断。

报告摘要说明纳入的人工确认负面证据数量；风险标签会合并已确认证据类型。
未纳入证据时使用“未纳入经人工确认的公开证据”，不做“绝对没有风险”的
断言。

报告输入哈希新增：

- 证据 ID；
- 风险类型；
- 标题和来源 URL；
- 正文快照 ID；
- 正文哈希；
- 截断状态。

因此证据决定或网页内容变化后会生成新版本，不会复用旧报告。

## 5. 接口

```text
POST /api/tasks/{taskId}/public-intelligence/evidence/{evidenceId}/content-snapshot
GET  /api/tasks/{taskId}/public-intelligence/evidence/{evidenceId}/content-snapshot
GET  /api/tasks/{taskId}/public-intelligence/content-snapshots
```

既有报告接口保持不变。

## 6. 测试与验收

自动化覆盖：

- Provider 重名、禁用配置、缺密钥启动校验；
- HTTP 查询参数、鉴权头、中文查询和结果解析；
- 429 显式失败；
- HTML 文本提取、内容哈希和内网地址阻断；
- 正文快照幂等；
- 人工确认、证据评分、报告生成和下载端到端；
- DOCX 中出现证据数量、风险类型、标题、正文摘要、来源和抓取时间；
- 未确认的大模型无引用线索不得进入报告；
- 非编辑 DOCX 包部件哈希保持不变。

模板结构审计结果：

- 2 个 A4 纵向分节；
- 参考文件和生成文件均为 23 个包部件；
- 缓存页数均为 14；
- 除 `word/document.xml` 和 `word/settings.xml` 外，其余包部件由测试验证
  字节级保持。

当前机器缺少 LibreOffice/soffice，无法完成 DOCX 页面 PNG 渲染。结构校验、
字段校验和包部件保留校验均已完成；视觉验收应在具备 Word 或 LibreOffice
的环境补跑。

## 7. 后续建议

1. 选定至少一个主流搜索服务和一个带引用的联网模型，配置测试账号；
2. 用 20～50 份历史报告建立检索召回、误报和人工确认基准；
3. 增加网页来源白名单/黑名单、robots/许可策略和来源权重；
4. 增加“完成运营确认”的正式接口，替代当前测试中的状态推进；
5. 在办公软件环境完成 14 页逐页视觉验收；
6. 搜索链路稳定后再接 ES。
