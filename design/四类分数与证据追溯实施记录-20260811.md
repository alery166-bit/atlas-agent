# 四类分数与证据追溯实施记录

## 1. 评分口径

平台当前保留并明确区分以下信息：

| 名称 | 来源 | 是否参与正式结果 |
| --- | --- | --- |
| 输入旧报告分 | 上传的旧 DOCX 解析结果 | 否；用于新旧变化对比 |
| ES 物化旧模型分 | 企业数据快照中的 `legacy_score` | 特征不完整时作为迁移规则安全基线 |
| 迁移规则计算分 | 迁移后的确定性规则引擎 | 是 |
| 事件保底分 | 运营确认且有证据的失联、欠薪、闭店事件 | 是 |
| LLM 建议分 | LLM 高置信风险类型按已发布事件保底规则映射 | 否；仅供运营参考 |
| 系统原始分 | `max(迁移规则计算分, 事件保底分)` | 是；不可被人工覆盖 |
| 当前人工分 | 运营人员调整结果，默认等于系统原始分 | 是；报告采用该分值 |

## 2. LLM 建议分边界

LLM 不直接生成任意数值，也不能改系统原始分或人工分。只有同时满足以下条件的建议才进入参考分映射：

1. 模型判定证据与目标企业相关；
2. 置信度不低于 80%；
3. 风险类型是已配置保底规则的失联、拖欠工资或门店关闭；
4. 使用任务冻结的已发布规则版本映射，多个建议取最高保底分。

模型建议分、建议风险等级、模型服务商、模型名称、依据证据 ID、规则版本和执行时间保存在模型研判作业快照中。模型建议为 8 分不代表企业正式得分为 8 分；证据仍须运营人员确认，确认后才会进入事件保底分。

## 3. 证据追溯

- 每条 `RiskRuleHit` 保留规则编码、名称、风险类型、分值角色、分值和引用列表。
- 事件保底规则同时引用事件/发现 ID 和证据 ID。
- 旧模型基线、迁移规则中间项和倍率继续保留在同一评分快照中。
- 控制台“规则与证据追溯”区逐条展示命中规则及引用；没有外部证据的聚合规则会明确标识其来源是数据快照或聚合计算。
- 人工调整继续独立保存调整前后值、原因码、文字依据、操作人和时间，不覆盖系统原始分。

## 4. 存储与接口

- 新增数据库迁移 `V15__add_model_score_advisory.sql`。
- 模型研判作业新增 `model_suggested_score`、`model_suggested_risk_level`、`model_score_evidence_ids` 和 `advisory_rule_version`。
- OpenAPI 契约同步声明上述字段，并明确其不参与正式评分。
- 控制台评分血缘同时展示旧报告分、ES 旧分、规则分、事件保底分、LLM 建议分、系统原始分和人工分。

## 5. 验证结果

- H2 从空库顺序执行 15 个迁移成功，兼容当前自动化测试环境。
- 模型研判后台作业测试验证：高置信闭店建议映射为 8 分、高风险，三条依据证据均保留，但证据状态仍为 `UNVERIFIED`。
- 风险评分测试验证：闭店保底命中同时保留发现引用和证据引用；人工改分后系统原始分不变。
- OpenAPI 契约测试通过。
- 控制台 ESLint 与生产构建通过。
